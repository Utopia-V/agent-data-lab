# 工作成果的组织与跨任务使用

本批结果见[项目交接报告](../results/2026-10-02-handoff/report.md)，以下保留实际实验条件。

## 本次要回答的问题

同一批原始材料和已完成工作，给成果添加可发现的用途、调用入口、适用条件和来源依赖，能否减少后续不同任务的重新查找、解释和错误？在说明已经相同的情况下，程序可操作的结构是否仍有收益？

此前连续实验让各组同样保留脚本和产物，改变的是来源观察；本批改变成果的组织方式。已有统一访问层的局部查询结论继续保留，不用本批代替。

## 场景与材料

使用 Repa 固定提交 `040aa16d7c7a142cdebf39388486c1bc65a98387` 的设计文档、TypeScript 实现、测试和包声明，以及单独固定的公开 Issue 快照。材料按原项目目录保存。实验只读 Git 对象，不读取当前工作区的未提交改动。

工作过程是项目交接。先完成接口清单、资源使用说明、接入任务归属三项工作，再处理参数筛选、跨模块接入判断、实现修改后的旧说明修订、先前未涉及的配置问题和最终组合交付。初始任务不提供后续题目。未来任务从不同消费者的需要出发，不要求模型为了使用候选 API 改写任务。

普通代码、检索、批量读取、原生查询和全部历史工件在各组保留。首批三项工作由同一模型一次完成，所得整个工作目录作为三组共同起点。首批出错时不替模型修复，错误与后续恢复一起记录。

## 条件

| 条件 | 实际差别 |
| --- | --- |
| files | 初始工作目录原样保留，自由检索、编程和组织 |
| documented | 在相同工作目录增加模型整理的工作说明，记录用途、工件位置、适用条件、来源和依赖 |
| structured | 与 documented 完全相同的说明内容，以结构化记录和普通 Python 查询函数交付，支持选择记录、直接取得工件和核对已声明来源的变化 |

先让模型只根据已经完成的工作生成一份共用描述，再确定性地渲染为 documented 的 Markdown 和 structured 的 JSON。转换不增加事实。来源 hash 由宿主从模型实际声明的文件计算，同样显示给两组；哈希变化只表示字节改变，不声称业务解释已经失效。未声明的依赖仍可能遗漏，不用评分答案补齐。

files 允许自行建立任何说明或索引。后两组的描述提取成本分别计入总成本；structured 的渲染、查询及维护成本也计入。两组不免费获得手工整理的正确解释。提示长度及工具说明是各自实际成本，不强行填充另一组 token。

各组采用相同原始资料和自动来源变化通知，不额外提供候选原文。结果直接由模型保存的文件交付，不经最终回答重新转录。交接时各组都开始新会话；后续连续保留会话。这只回答交接后的组织效用，完整创建流程另由端到端复测检验。

## 固定任务

初始工作：

1. 从实际内容协议生成已注册方法及必填、可选参数清单。
2. 结合实现与文档说明资源准备、临时持有和上传限额。
3. 根据 Issue 正文和固定代码明确已有资源能力及待接入任务的归属。

交接后的任务：

1. 为客户端生成参数检查清单，按 operationId 与 base 的要求筛选接口。
2. 为交互产物接入整理依赖，结合已有接口、模型工具与任务记录区分已实现和待实现部分。
3. 原始代码中的资源期限及上传限额改变，原文档暂未同步；更新实际行为说明，并判断不同宿主状态下的使用结果。
4. 查询此前未涉及的提示配置接口，检查旧成果是否被错误套用到新问题。
5. 把接口筛选、接入依赖、更新后的资源策略和配置入口组合为 JSON 与 CSV 交付物，保留前面的历史版本。

第三步是明确标注的受控源码变体：只在实验副本中修改默认持有期限和上传限额。每组得到相同 diff。它检验依据变化后的重新解释，不当作上游真实发布。

## 评分与比较

接口 oracle 来自固定源码中的 TypeBox 声明；资源行为由其实现与相邻测试核对；任务归属来自冻结 Issue 正文。候选组织模块不生成标准答案。配置问题使用实际源码中不同于内容接口的字段，避免错误复用仍得到相同结果。

正确性按实际交付文件检查。各项分别保留漏项、误报、过期值和失败原因；原始文件不因出错被删除。组合交付核对前后结果的一致性和更新值，不把文件存在当作任务完成。

模型指令允许附加来源和说明。评分核对必需业务字段，并要求 CSV 完整对应实际 JSON；合法的说明字段不算误报。初版评分对嵌套对象使用全量相等，曾把来源字段误判为错误。`handoff-v1.1` 只修复这项评分解释，用相同原始交付物重算并保留原评分，不重新调用模型或更改题目。

记录模型轮次、未缓存输入、缓存输入、输出、实际耗时、描述生成及维护开销。以完整序列为比较单位；首错传播不充当多份独立证据。模型分别使用 Astra 与 Luna，均为 high，条件顺序随机化。首批用于判断值得继续的机制，不能由同一份材料的重复任务外推出跨领域优势。

documented 与 structured 的差值检验可操作结构的增量；它们与 files 的差值包含整理说明的收益。若文档已取得相同效果，保留文档约定；若结构的优势覆盖建立和维护成本，再从原始材料开始独立形成工作表示，验证完整流程。若 files 自行组织后追平，不要求产品增加登记机制。

## 来源更新后再次交接

首批模型保留了最初登记，新任务结果继续保存在普通文件中。追加一项新会话任务，从每组最终的完整工件接手，使用新的上传大小和等待时长判断当前资源行为，并结合后来查到的配置接口。所选值在旧、新策略下产生不同结果。各组都知道原始来源相对上次工作没有再次改变，也都保留旧结果和新结果。

该任务在运行前另存题目、答案和输入哈希，作为同一工作序列的追加接续，不充当独立重复样本。它检验旧工作说明、当前结果和当前源码能否被正确区分；若只在同一会话中继续，模型可能一直依靠刚形成的上下文而未重新消费保存的结构。

运行入口：`uv run python -m agent_data_lab.handoff --output campaigns/<新目录>`。
再次交接使用 `uv run python -m agent_data_lab.handoff_resume --parent campaigns/<原目录> --output campaigns/<新目录>`。两个命令都会调用模型。

# 数据访问候选设计

## 当前取舍

对象保留原生内容和源端读写方式。公共约定涉及对象身份、查询范围、结果覆盖与来源定位；跨能力组合使用普通代码，来源内部使用原生查询。

对象身份与处理器身份分开。文件移动、更换解析器和替换查询实现不改变对象身份。本文将内容自身的标识称为对象引用，将处理查询的实现称为提供器。

显式引用由引用者对应的提供器提取。公共层按范围派发并组合结果，不要求把全部引用复制到中央持久索引。引用结果保留每次出现的位置、原始关系类型和读取版本；出现三次不合并成一条。

范围是显式引用的集合，空集合产生空结果。范围约束先于查询截断；输出展示的截断不改变底层结果。范围不自动沿链接递归扩张。

结果需要区分已完成的范围与未覆盖的范围。无查询实现、读取失败和结果截断不能当作零条匹配。未覆盖部分仍保留原生读取入口。

## 实验要裁决的选择

数据目录是否优于一份普通的来源说明，取决于真实模型是否减少发现和理解入口的往返。目录不成为直接读写的前置步骤。

统一寻址、范围与引用接口的收益需要与同样拥有语料说明、能自行编程的对照组比较。原型不引入新的查询语言，也不把所有业务记录转换成统一实体 schema。

跨来源相关性评分尚未定义。首轮实验使用可判定的过滤、关系与范围查询，不将来源内部的检索分数直接混排。

## 已撤回的选择

- 中央引用索引不再是公共层的必需职责。
- 动态查询结果不自动成为 Repa 学习语境的组成成员。
- 保存中间结果沿用变量、文件和已有资源引用，不建立额外的长期记忆机制。

# 从原始来源形成工作表示

本组实验承接原始数据到工作表示的缺口。此前合成任务预先给出了较完整的来源和字段说明，本组使用独立作者编写的 DABstep 任务，保留其说明文档与原生数据。目标是观察发现、理解、编程和交付的完整过程，并据此改进组织方式。

接续实验现采用工件协议 v2：每题结果使用独立路径，全部历史产物继续对模型可见。旧协议复用 `answer.json` 并在每题开始前删除前次结果，削弱了文件接续条件；旧序列作为诊断保留，其比较不作为完整工件保留条件下的效果证据。受影响的连续工作对照按新协议重跑。冷启动实验不受此问题影响。

## 资料与答案

来源为 [Adyen / Hugging Face DABstep](https://huggingface.co/datasets/adyen/DABstep)，固定提交 `8afcb4ee3df0d73da5e0cddfddfb55665b760169`，许可 CC-BY-4.0。使用公开 dev 集的十个问题及标准答案；七份 context 文件包括业务手册、CSV 交易记录与分类表、JSON 费率规则和商户资料。该数据集的交易记录为合成数据，分析规则和任务来自其公开基准。

下载文件逐项保存 hash。模型只见 context，不见 dev 标准答案、生成器、其他参与者提交或排行榜。此实验不向公开排行榜提交结果。

```bash
uv run python -m agent_data_lab.fetch_data
uv run --group environment python -m agent_data_lab.workflow --output campaigns/raw-discovery --tasks 70,1305,1681
uv run --group environment python -m agent_data_lab.episodes --output campaigns/retained-work
```

下载入口核对 `data-sources/dabstep.json` 中的固定版本和逐文件 SHA256，已有完整文件直接复用。后两条命令实际调用模型。

## 首轮条件

files 条件提供原始文件、shell、Python、Pandas、DuckDB。catalog 条件额外提供自动的来源 profile、Markdown 分段检索和原生 DuckDB 表入口。两组获得相同事实和第三方库；catalog 不预先提取费用适用规则、计算业务答案或调用额外模型。

catalog 是首批探针的历史条件。当前主源码已移除未被采用的 SQL 包装，默认比较 files 与 observed；复现历史条件使用报告中的冻结实现。

目录与分段由程序从原文生成，其实际构建耗时包含在工具与端到端耗时内。精确结果写入普通 JSON 文件，由宿主直接读取评分；不要求模型把已经算出的列表再次转录到最终文本。

初始调查使用原 dev 集的 70、1305、1681 三题，分别涉及解释手册、连接分类与规则、结合交易数据计算适用规则。先观察冷启动的来源发现和语义解释，再依据过程选择需要进一步实现的表示与维护能力。此批次是调查入口，不作为整个课题的完成条件。

## 后续完整过程

同一工作区继续处理相关问题，保留普通脚本、SQL 视图和产物；另在新会话中接续，以检验表示是否自足。随后改变原数据、手册规则或材料位置，检查重新解释和更新是否局限于实际受影响部分。基线也保留其自行构建的代码和表示，不通过反复清空基线制造优势。

来源、表示、计算和交付分别保留可定位证据。准备、发现、材料化、维护、消费的完整成本一起计入；未知格式、解释不确定和失效来源不能作为成功的空结果。

## 已观察的缺口与接续调查

首批六次运行中，三个 catalog 条件均未调用目录 API。题目 1305 的两种回答来自空列表含义的不同解释；1681 的两种回答来自日期措辞的不同解释；70 的错误回答把更高处理费推断为已有高欺诈罚款规则。这些轨迹不支持目录改善语义判断的结论。

下一组使用本项目定义的受控变体，不计作 DABstep 官方成绩。明确空列表不限制字段、只筛选题目指定条件、按规则等权平均。连续任务依次改变金额、费率记录、手册费率单位、不影响计算的说明、数据位置和业务分类。标准答案由宿主独立计算；变更计划先于模型运行冻结。

每组始终保留普通脚本、笔记和输出。conversation 组保留会话历史，workspace 组每题开启新会话但保留同一工作目录。Astra 和 Luna 使用相同材料与 high 思考强度。每次任务都说明来源可能已经更新，不把隐瞒变化作为实验条件。观察自行形成的工作表示能否正确接续，及数据变更、含义变更和无关变更各自的代价。

此组先测普通文件基线；只有轨迹显示仍有实际缺口，再决定引入何种维护能力。

## 自动观察的拆分对照

普通文件接续调查中，Luna 沿用了首次错误的空列表解释，也在手册费率单位改变后继续使用旧公式。Astra 在同样变化下保持正确。

下一组拆分两个候选行为，全部保留普通文件、编程能力与工作目录，不要求调用新 API：

- discovery：新会话首题附加根据题目词法检索得到的五个文档分段或表结构。使用已有目录实现，不新增人工业务解释；返回范围标明其并非完整语义解释。
- changes：后续题目附加源文件相对上次任务的增删改。较短文本附 diff，大文件只说明实际版本变化；未变化时给出这一事实。
- both：组合两者。
- none：不附加观察。

discovery 不在同一会话的每一题重复注入背景。changes 不重新注入未改变的正文。程序不决定业务结果、不阻止执行或要求批准，模型依据观察继续判断。记录自动处理的实际耗时与模型 token，分别观察首次解释和变化后的接续行为。

本次使用 Luna、conversation、每条件两次完整序列，条件顺序固定随机化。既有 Astra 正确序列用于理解模型差异，不与本组拼成配对效果声明。

随后增加 instructions 条件：只用文字规则要求保存可复用计算方式与依据，复用前核对字段含义、公式与范围约束，允许普通快照与 diff。不给额外来源观察，也不规定业务答案。用它检查已观察收益是否通过规则和原有工具就能取得。

首个接续试运行因评分器未接受题目允许的 `EUR` 前缀，在首题后中止；四次调用和工件保留，缺少完整 token 记录，排除出费用汇总。评分器修复后另建批次，后续模型原始结果在评分前落盘。

## 文件边界与来源范围

布局实验保留同一千条当前费率记录和两个问题的答案，将费率存储分别设为单文件、32 个分片、256 个分片加历史副本。手册明确当前表是哪些文件的并集，历史文件明确排除；不要求从列名猜业务归属。每题冷启动，比较普通文件与自动首轮观察，Luna / high。

这项实验检查事实与存储布局的分离：是否少读分片、是否错误纳入同 schema 的历史记录，以及自动结构提取的成本。没有增加有效业务事实或扩大统计样本量，不能把分片数量称作数据量增长。

## 中文材料与非计算任务

固定 Repa 提交 `040aa16d7c7a142cdebf39388486c1bc65a98387` 的十七份原文，针对学习语境生命周期、内容身份、前端与运行三个主题辨别设计陈述。模型需同时保存支持陈述的原文摘录和来源，答案由 CONTEXT 与对应 ADR 人工核对；不以匹配答案集合代替摘录检查。

初始 SQLite 分词没有切开中文自然语言问题，三个探针均返回空结果。后续实现使用 jieba 搜索模式为中文建词法索引，原文与定位保持不变。此组使用新实现快照，不与此前英文组混作同版本效果。比较普通文件与自动首轮观察，Luna / high。

## 压缩后的接续

复用 Codex app-server 的 `thread/compact/start`，在七步序列的第三步完成后进行原生压缩，随后改变手册规则并继续同一会话。none 条件直接接续；both 条件在压缩后重新提供当前相关原文与变更观察。保存压缩生命周期和可用的 token 统计，不导出压缩内部消息。该组检验保存在实验宿主的观察记录与模型当前有效上下文之间的区别，不另写压缩器。

## 复合分析与交互产物

新序列要求从原始材料形成费用匹配方法，连续处理按日、按月、费率反事实、月度背景变化、新会话中的另一商户，以及 CSV 审计表和自包含交互网页。网页内嵌的数据与 CSV 分别核对，浏览器交互另作检查。每个任务使用独立输出路径，保留此前全部产物。

标准答案由宿主独立实现。原始数据的日/月 ID 集合与 DABstep dev 的 1681、1753 完全相同；反事实按十进制计算为 `-0.94810300000000`，原 dev 的浮点答案为 `-0.94810300000017`，本序列金额判断采用绝对误差 `1e-9`。这属于受控变体，不计作官方基准成绩。

在 1 月 20 日追加一笔非欺诈交易，使整月金额跨过一百万欧元，而 1 月 10 日的交易行不变。正确的当天费用集合应移除 454、加入 602。随后更换商户与会话，再制作逐规则审计；最后调整规则 602 的 rate 并生成新版本报告。条件仍为普通原生文件与相关原文加变化观察，模型为 Astra、Luna，均使用 high。

## 含义与字段说明放在一起

local_contract 条件只把同一段补充解释从手册末尾移到费用字段及 null 说明旁，不添加业务事实、工具、自动检索或变化通知。原生文件组的读写与编程能力不变，继续使用工件协议 v2。Luna / high 分别在连续会话和只保留文件的新会话中各运行两条七步序列，检查改善来源本身的组织能否替代额外观察。

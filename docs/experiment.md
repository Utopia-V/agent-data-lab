# 实验协议

## 研究问题

在强模型拥有普通文件工具与编程能力时，附加的数据访问约定是否仍有独立收益？区分三种收益来源：数据说明、可复用的确定性处理、跨来源统一约定。

## 比较条件

| 条件 | 模型可见能力 | 用途 |
| --- | --- | --- |
| files | 原始语料、正常目录与格式说明、shell/Python | 普通文件工作基线 |
| described | files 加来源语义、字段含义与关联说明 | 测量数据说明的贡献 |
| interface | described 加可组合的范围、读取、引用查询接口 | 测量接口相对说明的增量 |

所有条件允许一次代码执行批量读取、循环和筛选。底层事实相同；不为 interface 条件预先提供其他条件无法获得的语义答案。

## 任务与评分

任务覆盖已知对象直接读取、穷尽枚举、跨来源连接、显式引用位置、限定范围后检索、未覆盖范围与损坏来源、重定位后的身份和版本变化。题目按实际需要选取这些行为，不强制每道题经历全部接口。

标准答案从生成器创建时的事实与独立检查得到。结果比较保留漏项、误报、定位错误、错误完整性声明和最终结果，不用总分掩盖具体失败。

首轮为探索实验。任务、语料 seed、条件、模型与思考强度配对固定，运行顺序随机化。根据轨迹改进接口后使用新实验版本；旧结果不被覆盖，也不把用于修改的样例称为独立验证。

## 测量

- 任务结果与覆盖声明的正确性。
- 实际发生的工具调用、模型调用（只有运行入口能可靠观测时记录）、耗时与报告的 token 使用。
- 工具交付字节数、截断与失败重试；这些指标独立报告，不换算成 token 或模型延迟。
- 实现和维护代价：额外源说明、适配代码、建立与刷新派生结构所需工作。

## 健壮性

确定性测试覆盖重复引用、代码块伪链接、空范围、重复范围成员、移动对象、过期版本、缺失与损坏来源、未支持的格式、查询范围遗漏、输出截断和未知对象。使用多个 seed 和变形测试，检查结果随移动、重排及加入无关数据的变化。

真实模型实验另外保留失败轨迹，判断错误发生在发现、参数、查询覆盖、结果解释还是最终回答。

## v1 具体执行

首轮使用 GPT-6 Astra、high 思考强度、120 份 Markdown 文档、一个 SQLite 数据库、JSONL 标注及 HTML 材料。任务固定为 lookup、latest、join、references、scoped、mixed、decision、empty；题目与标准答案在 `fixtures.py` 中生成并写入模型不可见的 manifest。

lookup 和 empty 检查简单任务的额外负担；latest 检查完整枚举与时间语义；join、decision 检查程序化组合；references 检查语法与出现位置；scoped 检查范围先于截断；mixed 检查部分查询、原生接续和最终未决范围。

每个题目和条件启动独立临时会话。三个条件的 run 工具一致，均拥有 bash、rg、Python 标准库及 CommonMark 解析器 markdown-it-py 4.2.0；interface 另外挂载 `access.py`。数据说明与 API 说明通过普通文件读取取得，该读取成本计入实验。模型不必使用提供的接口。

主测使用 seed 71。健壮性程序测试使用其他 seed；根据主测轨迹调整方案后，另用 seed 313、907 进行后续比较。条件顺序使用固定随机排列，每次至多并行三个任务。耗时包含临时会话初始化、推理和工具运行，实际工具运行时间独立记录。

模型调用次数取本机 Codex 0.159.2 app-server 的 `rawResponse/completed` 通知；仅保留完成次数及使用量元数据，其他 raw 内容在接收端立即丢弃。token 使用以 `thread/tokenUsage/updated` 的报告为准。输出字节数不转换为 token。

## 收束条件

完整保留产生结论的实现版本、实验参数与可重建材料。确定性行为成立后，依据配对模型实验决定保留、修改或撤回候选接口。收益不足时收窄到说明约定或源端辅助函数；不以已投入代码量决定保留。
